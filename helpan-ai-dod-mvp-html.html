§ 1

Purpose and how to use

This document serves two functions in a single reference. MVP Scope defines exactly what ships in Helpan AI v1.0. Definition of Done defines the quality bar that must be met at each stage before work can advance.

Critical rule: A feature is not "in MVP" unless it is also "done" by the criteria in this document. There is no MVP without DoD.

Use §3–§6 as the product boundary reference throughout the build. Use §7–§9 as the sprint gate and stage-advance checklist. Use §10 as the go/no-go checklist for v1.0 production release.

§ 2

Strategic context

Helpan AI is being built in direct response to the disintermediation thesis: AI agents will become the primary interface between consumers and their financial and commercial services within three to five years. Kenya is not immune. The Kirimon portfolio's response is to build the agent rail — and each consuming app's branded agent — before third-party agents arrive and absorb the customer relationship.

The two McKinsey reports informing this design (April 2026) are cited in full in Instruction Pack §4. Read §4 before this document if you have not already.

Silvia is starting the rail build today, 5 May 2026. This document governs that build from the first commit.

§ 3

MVP definition

Helpan AI v1.0 MVP is defined as: the minimum Helpan AI rail that allows at least two consuming apps to ship a production-grade branded Helpan agent — with full delegated authority, consent surface, notification routing, and payment orchestration — without building any agent infrastructure themselves.

"Production-grade" means: secure, auditable, regulator-compliant, observable, and recoverable from failure.

§ 4

MVP scope — what is IN for v1.0

Rail capabilities

  • Agent runtime (execution, tool calls, orchestration)
  • Briefing management (CRUD, types: alert / standing basket / scheduled action / threshold watch)
  • Matching engine (real-time event ingestion, briefing-to-event matching, match confidence scoring)
  • Delegated authority (issuance, validation, revocation; ≤5s propagation)
  • Helpan Console (shared React Native library; active authorities, activity log, one-tap revocation)
  • Audit log (immutable; 7yr retention for money-touching, 2yr all others)
  • Agent-to-rail dispatch (Kipkiren Pay, Identiti, Todoku)
  • Per-app safety policies (category whitelist, content moderation hooks)
  • Observability (success rates, latency, cost per app, alerting)
  • Operator console (audit review, safety admin, agent registration, scope catalogue)

Rail integrations

RailCapabilities consumed in v1.0
Identiti JWT validation, step-up token flow, consent record reads, event subscriptions (UserDeleted, AccountMerged, ConsentRevoked, KYCDowngraded)
Kipkiren Pay Payment, verification primitive, hold/release/escrow, refund, dispute, statement, programmable money/scheduled transfers, delegated authority validation endpoint
Todoku Notification dispatch (push, SMS, in-app inbox); structured request format; quiet hours and frequency caps delegated to Todoku

SDK

React Native client SDK covering full consumer-side surface (Instruction Pack §6.2). Documentation and integration guides for both flagship apps.

OAuth scope catalogue

Scope catalogue defined for all v1.0 consuming apps. Default posture: most restrictive. Manual approval for third-party agents in v1.0.

§ 6

Stage model

Stage 0
Specification

Design corpus complete. All hard blockers resolved. No code in production.

Stage 1
Internal Alpha

Rail running in staging. Internal team using it. Both flagship integrations wired in staging.

Stage 2
Closed Beta

Rail in production behind feature flag. Controlled set of real users on both flagship apps.

Stage 3
Production

General availability. All DoD criteria met. All v1.0 consuming-app integrations live.

Stage advance rule: All DoD criteria for a stage must be met and signed off before advancing. Partial completion does not qualify.

§ 7

Definition of Done

Stage 0 — Specification complete

Contracts and specifications

  • OpenAPI 3.x specification complete for all rail-side endpoints (Instruction Pack §6.1)
  • Delegated authority token contract complete and signed off by Identiti and Security (§6.4)
  • Step-up token contract joint with Identiti complete (§8.4)
  • OAuth scope catalogue v1 complete (§12.1)
  • Rail-to-rail contracts complete: Helpan AI ↔ Identiti, ↔ Kipkiren Pay, ↔ Todoku (§6.3)
  • Event bus contract complete (Output Plan item 6)
  • Kipkiren Pay gap analysis complete (§9.4)

Schema and data model

  • Full ERD complete for all rail-side tables (§7.1)
  • RLS policy specification complete for all tables (§7.4)
  • Audit log specification complete with retention rules (§7.3)

Security and legal

  • Threat model (STRIDE or equivalent) complete and reviewed
  • Per-app safety policy schema defined
  • Regulatory containment confirmed by legal (§9.3)
  • Behavioural data containment policy confirmed per app
  • ODPC registration alignment confirmed

Design and sign-off

  • Helpan Console design specification complete
  • Confirmation Memo produced and accepted by Chamia

Infrastructure

  • Supabase schema (af-south-1) deployed with full RLS
  • All rail-side endpoints implemented and passing contract tests
  • Delegated authority issuance, validation, and revocation working end-to-end
  • Revocation propagation to Kipkiren Pay and Todoku confirmed within 5-second SLA
  • Audit log writing and reading confirmed
  • Matching engine processing test events and firing matches

Integrations

  • Identiti JWT validation live in staging
  • Identiti step-up token flow live in staging
  • Kipkiren Pay agent-native endpoints live in staging (all v1.0 capabilities)
  • Todoku notification dispatch live in staging

Consuming apps and SDK

  • Helpan Klokd wired in staging — shift briefings, employer shift-fill, pay-on-completion via Kipkiren Pay
  • Helpan Lunch Drop wired in staging — ZoneFeed augmentation, weekly plan briefings, reliability nudges
  • Helpan Chapaa wired in staging — goal nudges, round-up, MMF suggest, credit unlock
  • Helpan [Family-Discovery App] wired in staging — briefings, matching, family-safe policy, Helpan Console
  • React Native SDK published to internal registry
  • Integration guide complete

Observability

  • All observability metrics instrumented and visible in ops dashboard
  • Alerting configured on critical thresholds

Stage 2 — Closed Beta

Production readiness

  • Rail deployed to production (feature-flagged)
  • DR drill completed and documented
  • Incident management runbooks complete
  • Load test completed against expected v1.0 agent volume
  • All Critical and High penetration test findings resolved

Consuming apps and users

  • Helpan Klokd live in production — closed beta (≥50 workers, ≥20 employers)
  • Helpan Lunch Drop live in production — closed beta cohort (≥50 users)
  • Helpan Chapaa live in production — closed beta cohort (≥50 users)
  • Helpan [Family-Discovery App] live in production — closed beta cohort (≥50 users)
  • Helpan Console UX validated with ≥10 real users
  • Operator console live for Kirimon ops team

Compliance

  • ODPC registration complete or confirmed in progress with legal timeline
  • Kenya Data Protection Act 2019 alignment confirmed by legal counsel
  • Audit log verified in production with retention policy active

Stage 3 — Production

Scale and stability

  • Zero Critical or High open security findings
  • P99 agent action dispatch latency ≤ 2 seconds under expected load
  • Rail uptime ≥ 99.5% over trailing 30 days
  • Revocation propagation ≤ 5 seconds confirmed under load
  • No data leakage incidents in closed beta

Consuming apps and OAuth

  • All four flagship integrations live with general availability (Helpan Klokd, Helpan Lunch Drop, Helpan Chapaa, Helpan [Family-Discovery App])
  • Helpan Lunch Drop live (or formally deferred to v1.1 with Chamia sign-off)
  • Helpan Console available to all users of all live integrations
  • OAuth scope catalogue published and documented
  • At least one third-party agent integration validated and live

Documentation and sign-off

  • All Output Plan items 1–16 complete and published
  • Reboot Pack v1.0 complete and accepted
  • Chamia (CEO & CPO) product sign-off
  • Silvia (CTO) technical sign-off
  • Legal compliance sign-off

DoD working rules

Binary criteria only. Every criterion is pass/fail. "Mostly done" is not done. Every criterion requires evidence — a deliverable, a test result, a sign-off. Regressions reset the stage. Security findings block stage advance.

§ 8

MVP launch criteria — v1.0 go/no-go

All criteria must be met. No exceptions.

Product

  • All four flagship integrations live and passing DoD Stage 3 (Helpan Klokd, Helpan Lunch Drop, Helpan Chapaa, Helpan [Family-Discovery App])
  • Helpan Console available to all users of both integrations
  • Family-friendly safety policy enforced and validated in production
  • Chapaa MMF rebalancing defaulting to suggest-only, confirmed in production

Security and performance

  • Zero open Critical or High security findings
  • Penetration test complete; all Critical and High resolved
  • Delegated authority revocation confirmed ≤ 5 seconds under load
  • No cross-app data leakage confirmed in closed beta
  • P99 dispatch latency ≤ 2 seconds under load
  • Rail uptime ≥ 99.5% over trailing 30 days

Compliance and operations

  • Legal sign-off: regulatory containment, DPA 2019, ODPC
  • Audit log live and verified in production
  • DR drill complete
  • Incident runbooks live and tested
  • Operator console live for Kirimon ops team
  • Reboot Pack v1.0 complete

§ 10

Known risks and mitigations

RiskLikelihoodImpactMitigation
Kipkiren Pay agent-native surface not ready when Helpan AI is ready High Blocks flagship integrations Gap analysis must close at Stage 0. Parallel build tracks.
Identiti step-up token contract takes longer than expected Medium Blocks high-stakes delegated authority flows Begin joint contract design immediately. Agree interim mock for staging.
Regulatory uncertainty on agent-initiated financial actions Medium Could require redesign of delegated authority model Legal sign-off at Stage 0, not Stage 2.
Third-party agent abuse (scope over-reach, data harvesting) Medium User trust and DPA 2019 exposure Most-restrictive default scope. Manual approval in v1.0. Anomaly detection.
Family-discovery app brand not locked before Stage 2 Low Integration guide cannot be finalised Working name acceptable for Stage 0–1. Must be locked by Stage 2.
Consumer inertia on Helpan Console adoption Low Consent surface underused; reduces audit value UX validation with ≥10 users at Stage 2. Console surfaced prominently in onboarding.
